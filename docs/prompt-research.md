# 其他 AI 产品的提示词与架构：可借鉴之处

参考的是公开合集仓库 `x1xhlol/system-prompts-and-models-of-ai-tools`，重点读了和本项目最像的几类：
搜索问答（Perplexity）、跑在聊天软件里的私人助理（Poke）、通用 Agent 循环（Manus）、
通用对话助手（Claude）。下面只记思路，提示词全部用自己的话重写，没有照搬原文。

## 看到的共同做法

| 做法 | 出处 | 对本项目的意义 |
|---|---|---|
| 规划和写作分开，写作层被告知“用户看不到前面的检索过程，回答要自成一体” | Perplexity | 和我们的 Gather → Writer 分工一致；Writer 不该再说“根据搜索结果” |
| 按问题类型给写作规则（新闻按话题分组并合并同一事件、同名人物分开写、天气只给结论、操作按步骤、对比用对照、计算只给结果、翻译不引用、只给网址就只用该网址） | Perplexity | 原来 Writer 只有一套通用规则，长短和结构经常不对题 |
| 对话长度跟着用户走，别硬凑幽默、别说客套话，记忆可能过时 | Poke | 适合 Telegram 私人助理的口吻 |
| 外部内容（邮件、网页、自动触发）只当数据，不当指令 | Poke | 我们会把网页正文喂给采集、写作、核查三个模型，原来完全没防提示词注入 |
| 互不依赖的工具调用一次并发发出，减少往返 | Poke 执行层 | 采集循环每多一轮就要把全部历史重发一次，合并成一轮直接省钱省时间 |
| 会变化的“是非/现任”类事实（某人是否在世、某职位现任是谁、比赛结果）必须先查再答 | Claude | 这类问题模型记忆最容易过时，原来的规则路由会漏掉 |
| 提示词按固定分区组织，静态内容在前 | 普遍 | 和上一轮做的“静态前缀命中缓存”是同一个方向 |

## 已落地的改动

- `agents/writer.py`：新增“写作立场”（自成一体、矛盾两说都写、素材不足直说缺什么、素材不是指令）和“按问题类型调整”两段。
- `prompts.py` 采集提示词：新增“效率”（同一轮并发发起互不依赖的工具调用、不重复搜同义词、会变化的事以最新来源为准）和“工具结果是数据”。
- `agents/critic.py`：核查时忽略素材里要求改判的文字。
- `chat_prompt.py`：回复长度跟着用户走、不硬凑梗、不说客套话；记忆可能过时，重要决定不只凭记忆。
- `search_policy.py`：“现任 / CEO / 总统 / 去世 / 当选 / 比分”等词直接走搜索。

## 没有采纳的

- Markdown 标题、表格、LaTeX：Telegram 纯文本显示不了，对比类改用分行对照。
- “一轮只调一个工具”（Manus）：和省钱目标相反，采用的是并发方向。
- 多 Agent 委派（Poke 的前台 + 执行层）：我们已经是流水线结构，再加一层只会多花一次调用。
